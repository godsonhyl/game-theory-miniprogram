# 牌桌互动与氛围 · 设计文档（2026-10-15）

> 状态：已评审通过（用户确认「好」）。第一期范围 = 筹码飞行 + 赢牌特效 + 表情互动 + 观战者互动。
> 后续方向 backlog：AI/练习/复盘、战绩深化（一个一个来，本期不动）。

## 0. 背景与目标

三选一方向（互动氛围 / AI 复盘 / 战绩深化）中先做牌桌互动氛围。目标：让牌局「有人气」——
赢牌有仪式感、真人之间能表达、观战者不再是哑巴。

约束（评审时确认）：

- **同步边界**：真人互动走既有 room-sync 轮询广播（与聊天不同步同一既有限制，1.5s 延迟可接受），
  不为表情开专用动作通道。
- **特效尺度**：允许引入少量资源。已实测余量：当前包 883KB / 红线 2MB，余 ~1.1MB
  （miniprogram_npm 占 524KB）。特效资源预算 **200~300KB**，本期预计用量 <50KB，无需分包。
- **不动引擎**：poker-core.js 零改动（无双副本同步成本）；不新增隐私声明项。

## 1. 总体架构：一条互动消息通道

四个能力共用一条「氛围消息通道」，复用现有 room-sync 语义，不新建云表：

```
发送端（任意真人：seated 或 standing）
  → 走既有动作上行（type: 'emote'，payload 单字段 { emoji }）
  → 房主 pendingActions 消化（rowSeat 断言防伪冒——他人不能替我发表情）
  → 放入房主行氛围队列 emoteQueue（[{seat, emoji, ts}]，滚动保留 10 条）
  → 随快照同批广播（无独立心跳级实时）
  → 镜像端读队列，只渲染 ts 在近 1.5s 内的消息（防重放）
```

- **AI 局**：表情直接本地入队渲染，零链路成本。
- **掉线/代弃等系统消息**：仍走本地 chatLog，不混入 emoteQueue。
- **上行失败**：静默降级（体验功能不弹错、不重试——与牌局关键上行的 syncFailToast 语义不同，
  刻意不接提示链路）。
- **断线重连**：镜像端不补偿历史表情，队列自然截断。

## 2. 能力清单

### 2.1 头像表情互动（P2）

- 点任何头像（含自己）弹出 6 格 emoji 轮盘：👏 🎉 😏 😅 🤡 💪。
- 发送后：座位旁冒出气泡 → 2s 上浮消散（transform + opacity keyframes）。
- 每座位同时只保留 1 个气泡，新顶旧（内存做按座位覆盖）。
- 频控：每座位 3s 一条（local 节流，超时静默丢弃不提示）。

### 2.2 赢牌氛围特效（P1）

- ① 胜者头像金光脉冲 2s（box-shadow/opacity keyframes，transform 兼容）。
- ② 牌型 ≥ 顺子时全屏星光粒子：**唯一引入资源处**——2~3 张小粒子贴图 PNG（合计 <50KB），
  CSS animation 驱动贴图位移离散分布，不逐帧 JS 计算。
- ③ 连胜徽章：连续赢 ≥2 手显示「🔥 xN」，随下一手牌局开始清除。
- 四色牌/动画开关沿用 settings.animation——**动画关则全部特效关**（统一入口）。

### 2.3 筹码飞行动画（P1）

| 场景 | 动画 |
|---|---|
| 下注/加注/跟注/全下 | 5~8 枚筹码代币从座位飞向底池，错峰 delay（40ms * i），到位后 pot 数字跳变 |
| 赢家收池 | 反向：底池飞向赢家座位，赢家 stack 数字上跳 |
| 边池多路 | 逐池串行播放（每池一组），不做并行（多路全下结算本就逐池） |

- 纯 CSS：筹码代币是 wxss 画的圆形+环形高光（零图片），translate + scale + opacity keyframes。
- 金额变化与动画解耦：数字跳变独立 keyframes（opacity 闪跳），动画失败不阻塞数字更新。
- animOn=false 时直接跳数字，零动画。

### 2.4 观战者互动（P3，基于 P2 通道）

- 站起者/未入座者可发表情与 3 条快捷语（「打得凶！」「稳住」「好牌!」）。
- 发送走同一 emote 通道（rowSeat 即观战者座位，standing 状态随快照本就广播）。
- 观战者头像在牌桌外圈显示（等待室已有 ring 坐标，游戏局新增站立指示点）。
- 渲染端对 standing 座位的表情气泡加「观战」角标，防混淆。

## 3. 数据与状态

- **emoteQueue**（房主行，随快照广播）：`[{seat, emoji, ts}]`，滚动 10 条。
- **本地渲染队列**：page 内 `emoteBubbles: {seatNo: {emoji, bornAt}}`，2s 自动消散。
- **连胜计数**：`winStreak[seat]`，牌局开始（handResult 累计）维护，下一手 startHand 清零。
- **筹码飞行**：纯 view 层一次性动画，无持久状态；出发条件由 render 比对前后快照的
  bets/pot 差值触发（现有 render 已有整帧 diff，加一个「金额变化 → 触发动画」回调）。

## 4. 错误处理

- 上行失败：静默降级（见 §1），不污染牌局关键路径。
- 云端不可用：现有 room-sync 降级本就回本地模拟，表情在 AI 局/降级局照常。
- emote 字段被伪造/超长：渲染端 emoji 白名单校验（仅 6 格轮盘内 6 个字符通过），
  非白名单直接丢弃。
- ts 异常（时钟慢设备）：渲染端以「收到时刻」为准做消散计时，不信任发送端 ts
  ——这与 seq 分道修复的踩坑同源（跨设备时钟不可信）。
