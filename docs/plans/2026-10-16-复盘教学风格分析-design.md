# 单局复盘 / AI 教学提示 / 风格分析 — 设计文档

> 2026-10-16 头脑风暴确认。方向：AI 对战/练习/复盘体验深化。三项一次设计、按三期落地。
> 分支：feat/next-brainstorm。数据全走本地（无新云端表、无新增隐私权限、无新增合规面）。

## 总原则

- **数据源全部本地**：复盘缓存用 `wx.setStorageSync`，不上新云端表（省服务端化成本与合规审查面）。
- **不碰引擎**：`core/poker-core.js` 双副本不动。复盘不重跑引擎（见 ① 的取舍说明）。
- **教学/提示仍限练习模式（AI 对战）**：与现有 `advise()` 同门槛（`renderAdvice` 的 `mode !== 'ai'` 拦截），好友房/匹配对战严格关闭——合规硬约束，不因新功能放宽。
- 体积红线：本地缓存上限 20 局 × ~4KB ≈ 80KB；包体积仍守 2MB。

## ① 单局复盘（第一期）

### 数据层：`utils/replay-store.js`（新）

- 存储键 `replay_cache`，环形上限 **最近 20 局**，FIFO 挤出最旧。
- 牌桌结算时（结算弹窗弹出点）调用 `addReplay(game)` 收割：
  ```
  { handNo, mode, mySeat, date,
    players: [{seat, name, isBot, startStack}],
    events: game.events,          // 引擎已记录全量事件（每街发牌/动作/结算）
    myHole: [card, card],
    result: { winners, rows, board } }
  ```
- 存储失败静默降级（本地缓存属体验优化，与 room-snapshot.js 同级定位）。

### 关键取舍：纯解析式复盘（不重跑引擎）

事件数组里已含每街公共牌/每动作/摊牌结果，直接按事件分组渲染即可还原任意时刻的牌面、底池、行动序列。不 re-seed 重放引擎的理由：
1. 免去「AI 决策在重放时已固化为事件」的注入复杂度；
2. 复盘只需「展示」不需「重新决策」；
3. 无 seed/跨版本风险，天然不可变。

### 复盘页 `pages/replay/`（新四件套）

- 入口一：牌桌页**结算弹窗**加「复盘」按钮。
- 入口二：我的页「历史战绩」列表加复盘入口（仅本地有该手缓存时显示）。
- 布局：纵向单列（不要求横屏），核心交互 = **街切换条**（翻前→翻牌→转牌→河牌→摊牌）。
- 切街驱动整个画面变化：
  ```
  setData({
    board: 累计到当前街的公共牌,
    pot: 该街结束时的底池,
    actionRows: 累计到该街的动作行（含高亮当前街）
  })
  ```
- 附加：「上帝视角」开关——展开所有玩家底牌（含对手，数据已在 events/快照内，属复盘场景正当可见）。

## ② AI 教学提示（第二期）

## ③ 风格分析（第三期）

### 定位与原则

- 入口：我的页「打法风格」section 内嵌入（不建新页面，省四件套）。
- 现状：profile.js 的 `style` 字段用云端胜率做粗糙代理（胜率 ≥65% 激进 / ≤30% 保守 / else 稳健）——只反映「赢不赢」不反映「怎么打」。本期补**行为**画像：翻前愿不愿进池（VPIP）、翻后主动还是被动（AGG）、敢不敢摊牌（摊牌胜率）。
- **数据源全部本地**：读 `replay-store` 的 `listAll()` 缓存存量，不上新云端表、无新隐私权限、无新合规面。
- **不碰引擎双副本**：只读复盘缓存的 events 序列，纯解析。
- **边界明确**（设计硬约束）：本地样本 < 10 局显示「样本不足，多打几局再看」不硬算；不做 GTO 精确对比（无权威基准，避免假权威）；四象限文案是**描述性**（你打得紧/松、凶/弱），不评判「对错」——避免对娱乐玩家说教。
- 保留旧 `style`（云端胜率代理）字段不动，与新 `styleAnalysis`（行为画像）分区职责，不互相取代。

### 新增 `utils/style-analyzer.js`

纯函数模块，零状态/零 RNG/零 wx 依赖（replay-store 负责读存储，本模块只吃已读出的 `list` 数组）。导出：

```js
module.exports = { analyze, VPipMin, AGG_PASSIVE, AGG_AGGRESSIVE };
```

#### `analyze(list)`

入参 `list` = `replayStore.listAll()` 返回的复盘记录数组，每条形如
`{ handNo, mode, mySeat, date, events: [{type,seq,street,seat,action,amount,...}], result: {type,winners,awards,evals}, ... }`
（`mySeat` 是该局「我」的座位，events 含补录的 `action:'blind'` 虚拟事件——见 replay-store.js）。

样本 < `VPipMin`（10）时返回 `{ sample, insufficient: true }`；否则返回：

```
{ sample, vpip, vpipPct, agg, aggText, sdRate, sdRatePct, sdWin, sdWinPct,
  quadrant, quadrantTag, observations: [...≤3条] }
```

**三个指标**（纯解析 events，按 `mySeat` 过滤我的动作）：

1. **VPIP（翻前自愿进池率）** = `自愿进池局数 / 总局数`。
   - 「自愿」= 翻前（`street === 'preflop'`）我有 `call`/`raise`/`allin` 任一动作。
   - `blind`（大小盲被动投）与 `check`（大盲无人加注免费看过）**不计**自愿——标准 VPIP 口径，被动投入不算主动参与。
   - 总局数 = `list.length`（每条 = 一局）。
2. **AGG（翻后激进度）** = `(raise+allin) / max(call, 1)`，统计范围 = 翻牌/转牌/河牌（`street !== 'preflop' && street !== 'showdown'`）。
   - `raise`/`allin` 计攻击；`call` 计跟从；`check`/`fold` 不入式。分母 `max(call,1)` 防 0 除。
   - 标准翻后 AF 口径——翻前加注是入池动作归 VPIP，不算攻击。
3. **摊牌胜率** = `摊牌且我获胜的局数 / 摊牌局数`。
   - 「摊牌」局 = `result.type === 'showdown'` 或 `result.evals[mySeat]` 存在。
   - 「我获胜」= `result.awards` 中有给 `mySeat` 的 `amount > 0`（用 awards 比 winners 稳——awards 是实际分钱）。
   - 摊牌局数 = 0 时 sdWin=0 且 observations 注「无摊牌样本」。

**四象限**（VPIP + AGG 双轴，固定阈值避免「假精确」）：
- VPIP 阈值：< 0.28 紧、≥ 0.28 松（28% 是 6 人桌常见分界）。
- AGG 阈值：< 1.0 弱（passive）、≥ 1.0 凶（aggressive）。

| | 弱（AGG<1） | 凶（AGG≥1） |
|---|---|---|
| 紧（VPIP<28%） | 紧弱（rock） | 紧凶（TAG） |
| 松（VPIP≥28%） | 松弱（calling station） | 松凶（LAG） |

`quadrantTag` = `tight-passive`/`tight-aggressive`/`loose-passive`/`loose-aggressive`（机读，供配色）。

**2-3 条观察**（描述性、不评判对错）：由指标生成，挑最显著的 2-3 条，例如：
- VPIP<0.20 →「翻前很挑剔，只打好牌」；VPIP>0.45 →「翻前入池很积极，手牌范围宽」
- AGG<0.7 →「翻后偏被动，多跟注少加注」；AGG>1.8 →「翻后很主动，频繁加注施压」
- 摊牌胜率<0.4 且摊牌局≥3 →「摊牌时赢面偏低，留意是否带弱牌到摊牌」
- 摊牌胜率>0.6 →「摊牌选牌质量不错」

#### 常量

`VPipMin = 10`、`AGG_PASSIVE = 1.0`、`AGG_AGGRESSIVE = 1.0`（同值，边界归凶），供测试断言。

### `pages/profile/profile.wxml` 风格画像区

在「打法风格」section 的 `style-card` 内，`style-row`（风格倾向 {{style}}）下方新增 `styleAnalysis` 区块，三态（样本不足 / 画像就绪 / 隐式空）：

```xml
<view class="style-insufficient" wx:if="{{styleAnalysis.insufficient}}">
  样本不足（{{styleAnalysis.sample}}/{{vpipMin}}局），多打几局再看风格画像
</view>
<block wx:else>
  <view class="style-row"><text class="style-k">打法象限</text>
    <text class="style-v {{styleAnalysis.quadrantTag}}">{{styleAnalysis.quadrant}}</text></view>
  <view class="style-row"><text class="style-k">翻前入池</text>
    <text class="style-v">{{styleAnalysis.vpipPct}}</text></view>
  <view class="style-row"><text class="style-k">翻后激进度</text>
    <text class="style-v">{{styleAnalysis.aggText}}</text></view>
  <view class="style-row"><text class="style-k">摊牌胜率</text>
    <text class="style-v">{{styleAnalysis.sdWinPct}}</text></view>
  <view class="style-obs" wx:for="{{styleAnalysis.observations}}" wx:key="*this">· {{item}}</view>
</block>
```

`vpipMin` 通过 data 注入（`VPipMin` 常量）。`wx:for` 用默认 `item`（无嵌套 for，默认别名满足 check-wxml 规则）。

### 测试 `test-miniprogram-logic.js`

新增 style-analyzer 测试块（接 advisor 测试块后、输出节前）：

- **纯函数单测**（构造 mock list，不依赖 replay-store）：
  - 样本不足：9 局 → `{ insufficient: true, sample: 9 }`；10 局 → 有画像。
  - 「全紧凶」样本（翻前只 raise、翻后 raise 不 call）→ quadrant=紧凶、vpipPct 反映、agg 高。
  - 「松弱」样本（翻前频繁 call、翻后只 check/call 不 raise）→ quadrant=松弱、agg<1。
  - 「全 fold 翻前」样本 → VPIP=0、quadrant=紧弱。
  - 摊牌胜率：3 局摊牌 2 胜 → sdWinPct='67%'；无摊牌局 → sdWin=0 且 observations 含「无摊牌」。
  - observations 数量 ≤3 且非空字符串。
- **profile.js 静态守卫**：两个 require 存在、`styleAnalyzer.analyze(replayStore.listAll())` 调用、`styleAnalysis` 写入 setData。
- **profile.wxml 静态守卫**：含 `styleAnalysis.insufficient` 分支、`styleAnalysis.quadrant` 插值、`styleAnalysis.observations` 的 wx:for。
- **合规/边界静态守卫**：style-analyzer.js 含「不接 LLM」「样本不足」注释；不含 `wx.request`/网络调用。

断言数硬口径：预计 +22~28（纯函数单测 ~16 + 静态守卫 ~8）。

### 不在本期范围

- 风格画像不做历史趋势图（「上周 vs 本周」）——本地只存 20 局，不够分时段。
- 不做「对比平均玩家」基准——无权威数据源，设计文档明确不做（避免假权威）。
- 三期全部落地后，复盘缓存 + 教学提示 + 风格分析形成「打-学-反思」闭环；后续接入服务端后可把这些本地数据上行做云端聚合（不在本期）。
