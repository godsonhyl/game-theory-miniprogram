# 单局复盘 / AI 教学提示 / 风格分析 — 设计文档

> 2026-10-16 头脑风暴确认。方向：AI 对战/练习/复盘体验深化。三项一次设计、按三期落地。
> 分支：feat/next-brainstorm。数据全走本地（无新云端表、无新增隐私权限、无新增合规面）。

## 总原则

- **数据源全部本地**：复盘缓存用 `wx.setStorageSync`，不上新云端表（省服务端化成本与合规审查面）。
- **不碰引擎**：`core/poker-core.js` 双副本不动。复盘不重跑引擎（见 ① 的取舍说明）。
- **教学/提示仍限练习模式（AI 对战）**：与现有 `advise()` 同门槛（`renderAdvice` 的 `mode !== 'ai'` 拦截），好友房/匹配对战严格关闭——合规硬约束，不因新功能放宽。
- 体积红线：本地缓存上限 20 局 × ~4KB ≈ 80KB；包体积仍守 2MB。

## ① 单局复盘（第一期）

### 数据层：`utils/replay-store.js`（新）

- 存储键 `replay_cache`，环形上限 **最近 20 局**，FIFO 挤出最旧。
- 牌桌结算时（结算弹窗弹出点）调用 `addReplay(game)` 收割：
  ```
  { handNo, mode, mySeat, date,
    players: [{seat, name, isBot, startStack}],
    events: game.events,          // 引擎已记录全量事件（每街发牌/动作/结算）
    myHole: [card, card],
    result: { winners, rows, board } }
  ```
- 存储失败静默降级（本地缓存属体验优化，与 room-snapshot.js 同级定位）。

### 关键取舍：纯解析式复盘（不重跑引擎）

事件数组里已含每街公共牌/每动作/摊牌结果，直接按事件分组渲染即可还原任意时刻的牌面、底池、行动序列。不 re-seed 重放引擎的理由：
1. 免去「AI 决策在重放时已固化为事件」的注入复杂度；
2. 复盘只需「展示」不需「重新决策」；
3. 无 seed/跨版本风险，天然不可变。

### 复盘页 `pages/replay/`（新四件套）

- 入口一：牌桌页**结算弹窗**加「复盘」按钮。
- 入口二：我的页「历史战绩」列表加复盘入口（仅本地有该手缓存时显示）。
- 布局：纵向单列（不要求横屏），核心交互 = **街切换条**（翻前→翻牌→转牌→河牌→摊牌）。
- 切街驱动整个画面变化：
  ```
  setData({
    board: 累计到当前街的公共牌,
    pot: 该街结束时的底池,
    actionRows: 累计到该街的动作行（含高亮当前街）
  })
  ```
- 附加：「上帝视角」开关——展开所有玩家底牌（含对手，数据已在 events/快照内，属复盘场景正当可见）。

## ② AI 教学提示（第二期）

- `utils/advisor.js` 新模块，纯客户端规则文案（**不接 LLM/外部服务**）。
- 翻前：起手牌分类标签（顶级对子/强同花连/中口袋对/高张系/边缘牌/垃圾牌——按 pair、同花、相连度、rank 强度映射）。
- 各街：`advise()` 已有返回（胜率、推荐动作、公共牌结构）→ 映射 6-10 条固定文案（如胜率 <0.38 且推荐弃牌 →「成牌无望，弃牌省钱」）。
- 呈现：牌桌页现有建议栏下方加一行小字，UI 不动布局。
- 门槛不变：练习模式（AI 对战）才启用，好友房/匹配关闭。

## ③ 风格分析（第三期）

- 入口：我的页战绩区入口项（先嵌入我的页，不建新页面，省四件套）。
- 算法：遍历本地复盘缓存的 events 中我的动作序列统计——
  - VPIP（翻前主动参与率）、AGG（bet/raise 占比）、摊牌胜率；
  - 四象限定位文案（紧弱/紧凶/松弱/松凶）+ 2-3 条具体行为观察。
- 总盈亏等图表数据仍走云端 poker_records（已有）；
- 明确边界：本地样本 < 10 局显示「样本不足」，不硬算；不做 GTO 精确对比（无权威基准，避免假权威）。
