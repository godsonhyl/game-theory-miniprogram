## 3. WXML 表达式引擎边界 ⚠️

**WXML 的 `{{}}` 不是完整 JS。** 这是本项目最隐蔽的一类 bug。

### 会被真机上传拒绝的写法

```xml
<!-- ❌ 历史事故：Bad attr 'class' with message: unexpected token ':' -->
<view class="… {{winFx && (',' + winFx + ',').indexOf(',' + item.seat + ',') >= 0 ? 'winfx' : ''}}">
```

WXML 解析器不接受**三元 / 逻辑运算里调用方法**，扫到 `? 'x' :` 的冒号就崩。

### 可以用的

```xml
<!-- ✅ 简单比较 + 三元 -->
{{!myReady && readyLeft > 0 ? '（' + readyLeft + 's）' : ''}}

<!-- ✅ 简单插值 -->
{{item.stack}}

<!-- ✅ 复杂逻辑 → JS 预计算 -->
<view class="{{item.cls}}">
```

### 铁律

> **复杂逻辑一律在 JS 里算好，WXML 只留简单插值。**
>
> 参考项目既有做法：`actCls` / `myActCls` / 座位卡 `cls` / `advCls`。

### 开发者工具不报错 ≠ 能上传

预览、真机调试都正常，**只有点「更新」上传才编译失败**。
所以 `check-wxml.js` 规则 3 是必须跑的第二道防线。

## 4. JS 编码约定

### 基本风格（与现有代码一致，无需格式化工具）

| 项 | 约定 |
|---|---|
| 缩进 | **2 空格** |
| 引号 | **单引号**（字符串内含单引号才用双引号） |
| 分号 | 有 |
| `const` / `let` | 优先 `const`，确需重赋值才 `let`，**禁用 `var`** |
| 文件作用域 | 模块级私有用 `const`/`let`，不挂全局 |

### ⚠️ 位运算必须加括号

`&` 优先级高于 `===`，历史上曾导致顺子判定全错：

```js
// ❌
if (mask & 1 === 0)

// ✅
if ((mask & 1) === 0)
```

### ⚠️ 决策输出进引擎前必须夹取到合法区间

```js
amount = Math.max(legal.minRaiseTo, Math.min(legal.maxRaiseTo, amount));
game.act(seat, 'raise', amount);
```

引擎是最后一道防线，任何 UI 算出的数字都不能直接喂进去。

### ⚠️ 不要在 render / 同帧流程里读刚 setData 的字段

`setData` 是异步的，同帧读 `this.data.xxx` 拿到的是**上一帧**的值：

```js
// ❌ render 内读 this.data.winFx —— 那是上一帧的
// ✅ 需要同帧一致就用实例字段
this._winFxSeats = winners.slice();
this.setData({ winFx: winners.join(',') });
```

### 命名

| 对象 | 约定 | 例 |
|---|---|---|
| 模块级常量 | `UPPER_SNAKE` | `READY_TIMEOUT_SEC` |
| 模块级可变量 | 同名驼峰（带注释说明） | `let game = null` |
| 实例字段 | `this.xxx` 小驼峰 | `this.pendingTimeUp` |
| 判定/纯函数 | 动词或 `isXxx` / `hasXxx` | `seatedOf()` / `snapToBlind()` |
| 事件处理 | `onXxx` | `onReadyTap()` |
| 下划线前缀 = 内部 | `_` | `this._winFxSeats` |

## 5. 错误处理与日志

### 异常绝不能向上抛到牌局链路

`render()` 内任何异常都必须**降级渲染 + 打日志**，绝不向上抛——否则
`startHand → render → advance` 链路断掉，牌局**无声冻结**。

```js
} catch (e) {
  console.error('[table] render 异常，已降级本帧', JSON.stringify({
    stage: 'render', mySeat: this.mySeat,
    message: e && e.message, stack: e && e.stack
  }));
  try {
    this.setData({ seats: [], board: [], legal: null, isMyTurn: false });
  } catch (e2) { /* 连降级都失败时放弃本帧 */ }
}
```

### 日志格式：带模块前缀 + 结构化

现状：`table.js` 里 18 处日志**全部**是 `console.error`，13 处带 `'[table] '` 前缀。

```js
console.error('[table] 跨设备同步不可用，已降级本地模式',
  JSON.stringify({ stage: 'bootstrap-sync', message: e && e.message }));
```

- 前缀 `'[table]'` / `'[room-sync]'` —— 一眼看出来源
- **第二个参数必须是 `JSON.stringify({...})`** —— 带 `stage` 便于定位
- 用 `console.error`，不用 `console.log`（噪音）
- **非关键路径的失败静默降级**（表情上行、氛围特效），但要留 `console.error`

## 6. 动画：重排红线

> **只动 `transform` / `opacity`，不动 `top` / `left` / `width` / `height`。**

目标 60fps。改 `top/left` 触发布局重排，低端机直接掉帧。

```css
/* ✅ */
@keyframes flyOut {
  from { transform: translate(...); opacity: 0; }
}
/* ❌ 改 top 会重排 */
@keyframes bad { from { top: 10rpx; } }
```

需要"关闭动画但保留数据"时，用 `.no-anim` 类兜底（数据仍下发，只摘动画）。

## 7. 云端安全红线 ⚠️

| 规则 | 说明 |
|---|---|
| **禁止手写 `wx.request` 访问 `/.cloud/**`** | 会绕过凭证注入。`npm run test:cloud` 会校验 |

| 可前端配置仅 `endpoint` / `publishableKey` | 其他一律不可暴露 |

### 隐私声明必须与实际调用精确一致

`miniprogram/.wbapp_*.privacy.json` 声明的接口要与代码实际调用一致，不多不少。

## 8. 金额与筹码

- 一律**整数筹码**，禁止浮点。
- 盲注固定 `sb: 10, bb: 20`（`game.sb` 是权威来源）。
- 自定义下注金额**必须吸附到小盲注整数倍**（`snapToBlind`）。
- ⚠️ **吸附在前、钳制在后**：上限常是零头（如剩余 157），
  先钳后吸会把它抬到 160 越界。

```js
// ✅
let v = this.snapToBlind(raw);
if (max && v > max) v = max;
```

- ⚠️ **输入过程中不吸附**：否则输「500」时第一个「5」就被改写。只在失焦时归一。

### 盈亏口径必须与结算同源

实时面板与结算单都读 `startStacks[mySeat]`，
**不允许各算各的**——否则出现「面板显示 +123、结算单 -45」这类最难排查的不一致。

## 10. 测试规范

### 框架

自研轻量断言脚本，**不装 jest/mocha**。mock `wx` / `Page` / `getApp` 后
真实加载页面 JS 驱动逻辑。

```js
function ok(cond, label) {
  if (cond) passes++;
  else failures.push(label);   // label 必须是人话，含实际值
}
```

### label 必须含实际值

```js
// ✅ 一眼看出问题
ok(dataStore.readyLeft === 30, '就绪倒计时 30 秒，实际 ' + dataStore.readyLeft);

// ❌ 失败了还得自己去猜
ok(dataStore.readyLeft === 30, '倒计时正确');
```

### 静态守卫要"锁结构"不"锁字符串"

```js
// ✅ 解析源码数值再判阈值 —— 参数在安全范围内调整不会误报
ok(cy - ry >= 10, '座位带最低点 ' + (cy - ry) + '% （≥10%）');

// ❌ 硬编码具体值 —— 调参就误报
ok(cy === 15, '座位最低点 15%');
```

**顺序类约束**用 `indexOf` 直接锁死：

```js
ok(iRoom < iSeat, '先回收房主身份再决定座位（顺序不能反）');
```

### ⚠️ 静态守卫的正则要注意

- 文件可能是 **CRLF 行尾**：`\n` + 字面空格匹配不到，用 `\s*` / `[\s\S]`
- 中文字符很占宽度：窗口 `{0,400}` 往往不够，酌情放大到 `{0,900}`
- **误报比漏报更烦人** —— 规则宁可收窄。`check-wxml.js` 规则 3 第一版就因为
  泛化到 `&&`/`||` 而误报 3 处线上正常写法，收窄为「方法调用 + 三元/逻辑运算」才准

### ⚠️ Bash heredoc 会吞反斜杠

调试正则一律用 Write 工具落临时 `.js` 文件跑，别在 heredoc 里写 `\s` / `\d`。

## 11. Git 提交规范

### commit message（中文）

```
<type>: <一句话摘要>

<空行>

<正文：为什么这么改，不是改了什么>

测试 mp 624 -> 634（+10）
```

type：`feat` / `fix` / `refactor` / `test` / `docs` / `chore` / `perf`

### 正文必须写「为什么」

改动理由、历史事故、设计取舍都写正文，这是评审唯一能追溯的东西。

### 同步远端的标准流程

```bash
git fetch --prune
git log HEAD..origin/master     # 看有没有新提交
git log origin/master..HEAD     # 看有没有本地未推
# 合并 → npm test → 结构校验 → node pack.js
git push origin master
```

⚠️ **必须检查有没有未合入的远端分支**（`git branch -r`）。
盲合有风险：先 `checkout -b tmp-verify origin/<branch>` 跑测试，
通过再 `--no-ff` 合入主干，验完删临时分支。

### 本机 Git 网络（企业网络 SSL 拦截）

```
http.proxy = http://127.0.0.1:7890        ← 必须 http，socks5 不支持
http.sslBackend = schannel
http.schannelCheckRevoke = false
```

`socks5://` 会报 `ServicePointManager 不支持具有 socks5 方案的代理`；
`openssl` 后端会报 `unable to get local issuer certificate`。

⚠️ 环境变量 `HTTP_PROXY` 是工具内部代理，**不能用于 git**。

## 13. 布局约定

### 中央盘面 z-index 必须高于座位

```
.pot-row / .board-row  z-index: 5
.seat                  z-index: 3
```

座位块是「锚点向下延伸」的（头像 + 名牌 + 标签 + 手牌），几何上**必然**与中央重叠。
重叠时的正确方向是「**中央压住牌背**」，不能反过来把底池/公共牌糊掉。
两者各有 `::before` 不透明底盘兜底。

### 按钮文案不要把次要提示塞进同一行括号

```xml
<!-- ❌ 宽度不足会从中间折断成两截 -->
<button>开始游戏（至少 2 人）</button>

<!-- ✅ 主副两行，主标题 nowrap -->
<button class="start-btn">
  <text class="sb-main">开始游戏</text>
  <text class="sb-sub" wx:if="{{!canStart}}">至少 2 人</text>
</button>
```

### 按钮文案长度

微信 `showModal` 的 `confirmText` / `cancelText` **≤ 4 字符**，超长真机静默失败
（开发者工具**不校验**）。

## 14. 身份与状态：权威来源不可靠派生

⚠️ **身份判定绝不能由 URL 参数独断。**

URL 可分享、可伪造、可丢失。房主从自己分享出去的卡片重进就会丢失身份
（分享链接不带 `own=1`）。

**权威必须在服务端用不可伪造的字段**：`poker_rooms.owner_id`（由服务端 `auth.uid()` 写入）。

**顺序铁律**：先定身份再定派生状态，否则会出现「按访客算完座位再切成房主」的错乱。

同理：
- **同一用户在同房间恒有且仅有一座** —— 源头释放 + 云端收敛 + 渲染去重，三层保障
- 盈亏基准用 `startStacks`，缺失兜底为**当前筹码**（视作 0 盈亏），
  **不要用常数兜底**（曾凭空记出 ±几百 的假盈亏）
