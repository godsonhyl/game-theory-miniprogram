# 上传体验版操作指引

> 已确认：**体验版不需要提审，也不需要版号**。这是与「正式发布」的本质区别。
> 下面是把本项目跑成体验版的完整步骤。
>
> 📌 完整的打包 / 上传 / CI 说明见上级目录的 **`发布指引.md`**（含命令行上传与 zip 打包）。

---

## 一、前提：你需要什么

| 项目 | 要求 | 说明 |
|---|---|---|
| 微信开发者工具 | 稳定版 | [developers.weixin.qq.com](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html) |
| 小程序账号 | 已注册 | 注册时选主体类型；**个人主体即可**（体验版不需认证） |
| AppID | 已有 | 注册后即可获取 |

**主体怎么选？**
- 体验版阶段：**个人主体即可**，不需要企业认证、不需要 300 元年费。
- 但要注意：个人主体**不能开通微信支付**，后续做房卡充值会受限。
- 如果打算正式做商业化，建议直接注册**企业/个体工商户**主体。

## 二、导入项目

1. 打开微信开发者工具 → 右上角「导入项目」
2. **目录选择 `poker` 目录**（注意：是 `poker`，不是 `poker/miniprogram`）
3. AppID：填你自己的（`project.config.json` 里现在是 `touristappid` 游客模式，需替换）
4. 后端服务：本地演示阶段选**不使用云服务**

> ⚠️ 目录说明：`poker/project.config.json` 中配置了
> `"miniprogramRoot": "miniprogram/"`，指向的是**子目录**。
> 因此导入时选 `poker`，开发者工具会自动去 `poker/miniprogram/` 找 `app.json`。
> 选 `miniprogram` 反而会因为找不到工程配置而报错。
>
> 如果你把 `project.config.json` 挪进了 `miniprogram/`，那才选 `miniprogram`。

## 三、本地验证（上传前必做）

在开发者工具里逐项确认：

- [ ] 首页正常渲染，模式卡片可点击
- [ ] 点「AI 对战」能进牌桌
- [ ] 牌桌横屏显示，6 个座位环绕排列
- [ ] 轮到你时操作按钮出现，能正常跟注/过牌/加注
- [ ] 滑块能拖动，5 个快捷加注可用
- [ ] 能完整打完一手牌并看到结算弹窗
- [ ] 点「下一手」能重开
- [ ] 真机预览（建议）：在手机上试一次触屏体验

**自动化验证**（已在项目中提供，可随时跑）：

```bash
cd poker
node test-core.js                      # 引擎 128 项断言
cd miniprogram && node test-miniprogram-logic.js   # 页面逻辑 25 项断言
```

## 四、上传体验版

1. 开发者工具 → 右上角「上传」
2. 填写：
   - **版本号**：`0.1.0`
   - **项目备注**：`体验版：好友房+AI对战，含边池与牌力分析`
3. 点确认，等待上传完成

4. 登录 [mp.weixin.qq.com](https://mp.weixin.qq.com)
   - 左侧「管理」→「版本管理」
   - 找到刚上传的**开发版本**
   - 点「设为体验版」

5. 「管理」→「成员管理」→「体验成员」
   - 添加体验者的微信号（最多 15 个）
   - **只有被添加的微信号才能打开体验版**

6. 在版本管理页获取**体验版二维码**，发给体验者扫码即可。

## 六、当前代码状态（诚实说明）

这份体验版是**功能演示**，不是可上线的商业版本。上传前请了解：

### ✅ 已实现且已验证

- 完整德州扑克规则（四轮下注、9 种牌型、边池、不足额全下）
- 6 人桌、5 个 AI 对手（AI 决策含位置与风格参数）
- 发牌动画、下注反馈、赢家高亮、结算弹窗
- 实时牌力分析（蒙特卡洛胜率 + 听牌检测 + 所需赔率）
- 微信静默登录（当前为本地模拟身份）
- 房间号创建与分享文案
- 个人战绩页

### ⚠️ 演示态实现（上线前必须替换）

| 项 | 当前 | 上线需要 |
|---|---|---|
| 牌局执行 | **跑在小程序本地** | 迁至服务端，客户端只渲染快照 |
| 洗牌种子 | 本地生成 | 服务端持有，客户端不可见 |
| 登录 | 返回本地 mock openid | 服务端用 code 换 openid + session |
| 房卡扣减 | 本地 `roomCards--` | 服务端事务扣减 + 幂等（order_id） |
| 好友房 | 仅生成房间号，无真实多人 | WebSocket 实时对战 |
| 战绩 | 未写入 storage | 服务端持久化 |
| 商城 | 弹「开发中」 | 接入支付（个人主体不可用，需企业主体） |
| 快速匹配 | 已默认关闭 | 需先过合规 |

> ⚠️ **最关键的一条**：当前牌局逻辑跑在客户端。
> 正式上线必须把 `core/poker-core.js` 放到**服务端**执行，
> 小程序侧只用 `game.snapshot()` 渲染。
> 这不是为了防作弊的锦上添花——**客户端可被任意篡改，不做服务端权威等于把所有筹码放在客户端手里**。

## 七、审核风险提示（仅针对将来的正式版）

体验版不过审，但**提交审核发布时会严格检查**：

1. **版号是硬门槛**。德州扑克属棋牌类游戏，无版号无法以游戏形态独立上架。
2. **「行动建议」在竞技房必须关闭**。已在代码注释与界面免责标注中提示，
   但最终需产品与合规团队书面确认。
3. **类目必须与实际功能一致**，不能虚标。
4. **房卡消耗文案不得涉及货币化表述**。
5. **ICP 备案**是提审前置条件，需提前启动。
6. **实名认证**接入是合规硬性要求。

建议：合规推进（P0）与功能开发并行，不要等开发完才查资质。
